# クイックスタート

このページは「インストールできた」から「本物を一度走らせて、画面に出ているものを理解した」までを扱う。4 段階、順番どおりにやる:
まず最も安い一発で認証情報とバイナリの両方が通っていることを証明し、次にコードを一行も書かずに完全な workflow を一度走らせ、
それから走っている最中に口を挟む方法を覚え、最後にスクリプトに組み込んで無人で走らせる。

前提は一つだけ:`flower` がインストール済みで、PATH に入っていて、認証情報が設定済みであること。まだの場合は[インストール](install.md)を先に。

## 第一歩:最も安い一発で確認する {#冒烟}

いきなり完全な workflow を走らせない。まず単一 agent・読み取り専用ツールで一発打って、認証情報とバイナリの両端が通っていることを証明する:

```bash
flower -v -w /path/to/any/repo once "读一眼这个仓库,一句话说它是干什么的"
```

| この部分 | 何か |
|---|---|
| `once` | 単一 agent を一度走らせる:要件を聞かない、目標を立てない、人を派遣しない |
| `-w PATH` | agent の作業ディレクトリ。指定しなければカレントディレクトリ |
| `-v` | 走り出す前に有効な認証情報の設定を出力する。token は先頭 4 桁だけ残す |

`once` はデフォルトで 3 つのツールしか渡さない —— `Read`、`Glob`、`Grep`。何も書けないので、この一発は安い。
実測値の参考:Opus 5 に 100 万窓を組み合わせてサードパーティゲートウェイ経由で、**単一ターンの最低価格は $0.1741**。安いモデルならさらに低い。

!!! tip "インストールページから来た人はそのまま飛ばしてよい"
    [インストール](install.md)ページの「インストールできたか確認する」で走らせるのがこのコマンドそのもの。走らせ済みなら先へ進んでよい。
    以下はその出力の読み方の説明にすぎない。

実行すると、この形が見えるはずだ —— 数字と本文は違ってよいが、**アイコンは違わない**:

```text
ANTHROPIC_AUTH_TOKEN = sk-1***(共 19 位)
ANTHROPIC_BASE_URL = https://your-gateway.example.com
ANTHROPIC_MODEL = claude-opus-5[1m]
- 验一下凭证…
  ~ 先看目录结构,再挑一两个文件读
  * Glob **/*.py
  * Read README.md
  这是一个用 Rust 写的命令行 HTTP 压测工具。
  - 累计 $0.00 · 0:00
  + 完成 4 轮 · $0.0932 · 用时 0:00
```

4 つのことを見分けられるようにしておく。後の段階はすべてこれに依存する:

- 最初の数行は `-v` が出力した有効な設定。**ゲートウェイを間違えていたら一目でわかる** —— このスイッチが存在する主な理由がこれだ。
- `- 验一下凭证…` は走り出す前の実際の API プローブ。認証情報が拒否されると `! 凭证被拒:…` を出力し、その場で再設定するか聞いてくる。
  接続できない場合は `(探针没打通:… —— 当作网络问题,照常开跑)` を出力し、本来問題のない token を**再設定させたりはしない**。
- アイコンは一律 ASCII:`~` 思考、`*` ツール呼び出し、`>` 派遣、`+` 成功、`x` 失敗、`?` 質問、`<-` 前回に接続。
  emoji ではない —— emoji と罫線文字はターミナルのグリフフォールバックを引き起こし、実測でターミナルを 2 回クラッシュさせた。**このドキュメント内のすべてのターミナル例は
  この ASCII セットを使っており、あなたの画面とまったく同じだ。**
- `+ 完成` の行の `$` は本物。`累计` と `用时` は `once` の経路では常に 0
  (イベントごとにレンダラを新規作成するので、状態が積み上がらない)。

この一発が通れば、認証情報・ゲートウェイ・モデル名・同梱バイナリがすべて正しいということだ。通らない場合はインストールの範疇なので、[インストール](install.md)へ戻る。

## 第二歩:コードを書かずに完全な workflow を一度走らせる {#跑一次}

コードは一行も書かない。**shell で引用符を打つ必要もない**。プロジェクトディレクトリに入って、そのまま:

```bash
cd /path/to/your/project
flower
```

何をしたいか聞かれ、カーソルが `>` の位置で止まる:

```text
要做什么? 一句话就够,回车开始(Ctrl-C 退出)
> 帮我做一个 X
```

この行は標準入力を読んでいて、**shell の解析を通らない** —— 全角引用符、空白、感嘆符をそのまま打てる。

Enter を押すと 3 つの step に沿って進む。画面の `==` の横線 1 本が[step](../reference/glossary.md#步骤)の境界で、
右側の `1/3` が進捗だ:

```text
== 确认需求 ======================================================== 1/3

  ? X 要跑在什么环境上?
     1) 只在我这台 macOS 上
     2) Linux 服务器
     3) 两个都要
你的回答 (回车=跳过,让它自己判断) > 1
  + 只在我这台 macOS 上

  ? 「做完了」以什么为准?
你的回答 (回车=跳过,让它自己判断) > 能跑起来,并且 pytest 全绿
  + 能跑起来,并且 pytest 全绿

  + 完成 9 轮 · $0.53 · 用时 6:02

== 设定目标 ======================================================== 2/3

  ~ 把这份需求拆成能当场验证的条目
  + 完成 12 轮 · $0.41 · 用时 9:06

== 干活 ============================================================ 3/3

  ~ 先看一眼现在有什么,再决定第一刀切哪
  * Read README.md
  > 派人 coder 实现 X 的第一版,带最小测试
  先让 coder 把骨架搭起来,我再看要不要拆第二个人。
  - 上下文 36.8K · 累计 $0.94 · 12:44
  + 完成 12 轮 · $12.34 · 用时 52:53
  + 完成 37 轮 · $1.40 · 用时 58:19

总花费 $14.68 · 清单 /path/to/your/project/runs/manifest.json
```

もう少し見ておく価値がある箇所が 3 つある:

- 最後の 2 行の `+ 完成` は重複ではない。1 行目は作業のターン、2 行目は**verdict** のターン ——
  verdict は自分の session で走るが、**別の `==` 横線を立てない**。`干活` という step の内部の 1 ターンだからだ。
  [run manifest](../reference/glossary.md#运行清单)での名前は `干活·判定#1`。
- `+ 完成` 行の `$` は**このターン**の金額、`用时` は**走り出してから現在まで**の累計時間。2 つは別の尺度だ。
- `- 上下文 … · 累计 … · …` のようなステータス行は[main thread](../reference/glossary.md#主线程)にだけ追従し、
  subagent のコンテキストは含まれない。subagent のツール呼び出しはデフォルトで表示され、`|` の縦線の後ろにインデントされる。
  subagent が**話した内容**は `-v` を付けないと見えない —— あれは現場であって、決定ではない。

### 画面に出ているこの 3 つの step は何か {#三步}

| 画面の step | 誰が走るか | 何をするか | 何に凍結されるか | 詳細 |
|---|---|---|---|---|
| `确认需求` | [clarifier](../reference/glossary.md#确认者) | 質問するだけで手を動かさない。**明確になるまで聞き、ターン数上限はない**。最後に 4 セクションの[brief](../reference/glossary.md#需求确认书)を出力する | `.flower/notes/需求.md` | [clarify](../guide/clarify.md) |
| `设定目标` | [judge](../reference/glossary.md#判定者) | brief を「目標 + 判定リスト」に翻訳する。各項目はその場で検証可能でなければならない | `.flower/notes/目标.md` | [goal guard](../guide/goal.md) |
| `干活` | [coordinator](../reference/glossary.md#协调者) が [subagent](../reference/glossary.md#subagent) を派遣して作業 | coordinator が作業を分割して派遣し、レポートを読み、決定する。各ターンの終わりに**作業に参加していない** judge が独立して「終わったか」を判定し、達成していなければ差し戻して続行させる | コード自体 | [goal guard](../guide/goal.md) |

最初の 2 step は [clarify](../reference/glossary.md#前置确认) と [goal guard](../reference/glossary.md#目标看守)
という 2 つの機構の実装であり、3 番目の step はその 2 つが合わさって管理している区間だ。デフォルトで verdict は最大 3 ターン(`--rounds`)、
`--no-goal` で丸ごと無効化できる —— 無効にすると「本人が終わったと言えば」本当に終わったことになる。

verdict の結論は 3 種類だけ:達成、未達、**この環境では検証できない**。後の 2 つは別の結論だ ——
「ここでは検証できない」は絶対に合格判定にはならず、止まってあなたに聞く。

完全な 1 回の実行は安くない。実測値の参考:[HT002](../cases/ht002.md) は既存プロジェクトを macOS にインストールして動かすまでで
4 step、約 1 時間、**$38.24**。[HT001](../cases/ht001.md) はゼロからターミナル IDE を書いて
**10.4 時間、$171.62**。先に何を聞かれるか見てから続けるか決めたい場合は `--clarify-only` を使う。

### 質問への答え方 {#答提问}

`?` で始まる段落はあなたへの質問だ。答え方は 3 通り:

- **番号を打つ**(`1` / `2` / `3`)—— その項目を選ぶ。画面には `+ <選ばれた項目>` が 1 行返る。
- **そのまま打ち込む** —— 自由回答。選択肢の中でなくてもよい。
- **そのまま Enter** —— スキップして自分で判断させる。画面には `. 已跳过` が 1 行返る。

デフォルトで 1800 秒待つ(`--timeout`)。誰も来なければ
`! 无人应答 —— 它会自己判断,把假设记进「未知与假设」` を出力し、そのまま先へ進む。ハングしない。
質問回数は**デフォルトで無制限**(`--asks` のデフォルトは `-1`)。正の数を渡せばハードな上限になり、使い切ると `! 提问额度用完` を出力する。

### もう一度走らせれば前回の続きになる {#再跑一次}

同じディレクトリでもう一度 `flower` を叩くと、最初の一文が変わっている:

```text
接着上次? 直接回车 = 接着做;也可以说点新的;/new = 重开一件事(Ctrl-C 退出)
> 顺便支持代码块高亮
<- 在 ~/proj 接上上次  需求已确认 · 目标 7 条 · 干活上下文 71.4K · 第 3 次唤醒
```

`<-` の行は[wake](../reference/glossary.md#唤醒) バナーで、このディレクトリの現在の状態を報告している。
要件をもう一度問い詰め直すことはなく、目標を再設定することもない。プロセスが kill されても、マシンが再起動しても同じだ。
このとき打った一文は `需求.md` に追記され、**判定リストの再導出をトリガーする** ——
再導出しなければ judge が読むのは古いリストのままで、新しく足したことは verdict に一切入らない。
詳細と代償(コンテキストは増え続ける)は[continuity](../guide/continuity.md)を参照。

前回の続きにしたくなければ `/new` と打つ:直前の要件、目標、[lineage](../reference/glossary.md#血缘)
は `notes/archive/<タイムスタンプ>/` に**移動**され(削除ではない)、最初から始まる。

## 第三歩:走り出した後も、あなたは口を出せる {#插话}

画面の一番下には常に入力できるプロンプトが 1 行ある。飾りではない —— 出力ごとにその前で消され、後で再描画されるので、
**ログに押し流されて上へ行ってしまうことがない**。文言は 2 種類で、「未回答の質問があるかどうか」で切り替わる:

```text
你的回答 (回车=跳过,让它自己判断) >
(直接说 = 加需求,下个检查点送达;? 开头 = 顺便问一句,不打扰它干活) >
```

未回答の質問がないときは、2 つのことができる。

**そのまま一文打つ = 要件を追加する。** 中断はされず、次に受信箱を確認したときに見る。受領通知はこんな形だ:

```text
+ 收到 (它下次查收件箱时会看到;已追加进确认书)
```

「brief に追記済み」というのが重要だ。この一文は同時に `需求.md` にも落ちるので、step の境界を越えて生き残る ——
次の step は新しい session で、凍結物しか読まない。spill しなければ言ったことは無かったのと同じになる。

**`?` で始める = ついでに一言聞く。** 別の読み取り専用 session を立てて答える。手元にあるのは直近 60 件のイベントと
[workbench](../reference/glossary.md#工作台)の中身だけだ。この側道は
[oracle](../reference/glossary.md#旁路顾问)が走らせ、デフォルトの上限は 12 ターン / $0.5:

```text
? 现在到哪了
# 旁路
  在干活第二轮,coder 刚补完 parser 的测试,正在跑第三次验证。
  ($0.0123,没有打扰正在跑的运行)
```

**答えたら捨てる** —— その問答はこの run のコンテキストに入らず、費用も主 run manifest に入らない。
`runs/aside/` の下に自分専用の 1 件として記録される。だから聞いても run に影響しないし、その金額が計上されるのを惜しむ必要もない。

!!! warning "全角の `？` は認識されない。半角の `?` でなければならない"
    側道の問答の判定は**半角** `?`(ASCII `0x3f`)のみを見る。中国語 IME がデフォルトで打つ全角 `？` は認識されない ——
    その行は「要件を追加」として受信箱に送られ、**エラーにもならない**。ただ、あなたが待っている回答が永遠に来ないだけだ。
    これはコード中の書き間違いで、既に不具合リストに記録済み。直るまでは、`?` を打つ前に IME を英語に切り替えること。

ついでに Ctrl+C について:実行中の 1 回目の押下は**このターンを中断して一言言う**であり、終了ではない。

```text
! 已打断这一轮。正在跑的 subagent 会丢掉半成品。
  要说什么?(直接回车 = 什么都不说,接着跑;再按一次 Ctrl+C = 退出)
>
```

もう一度押して初めて実際に終了する。(最初の `要做什么?` プロンプトで Ctrl-C を押した場合は即座に終了し、`已取消` を出力する。)

## 第四歩:スクリプトに書き込む {#脚本}

要求は引数として直接渡すこともできる。スイッチは要求の前でも後でもよい:

```bash
flower "帮我做一个 X"                      # 诉求当参数
flower --rounds 5 "帮我做一个 X"           # 开关在前
flower "帮我做一个 X" --rounds 5           # 开关在后,等价
echo "帮我做一个 X" | flower --timeout 0   # 管道喂标准输入,全自动
```

スイッチだけ渡して要求を渡さないのも可 —— `flower --clarify-only` は先に何をしたいか聞いてから進む。

**なぜ「Enter を押してから入力する」経路を残しているのか。** コマンドラインのあの引用符は純粋な負担だ。実測で踏んだ:
閉じ引用符を全角の `”` で打ってしまい、zsh が本物の閉じ引用符をずっと待ち(`dquote>` の継続プロンプトに落ちる)、
プログラムがハングしたように見えたが、実際には一度も起動していなかった。素の `flower` は標準入力を読み、shell の解析を通らないので、
全角引用符、空白、感嘆符、改行がすべてそのまま打てる。パイプの経路も同じ入口を通る ——
標準入力がターミナルでないときはプロンプトヘッダを出さず、そのまま 1 行読む。

!!! danger "無人運転では `--timeout 0` を明示的に渡さなければならない"
    パイプ、`nohup`、CI では質問に答えられる人間がいない。`--timeout 0` を渡さない場合:最初の質問は
    「入力が閉じている」ためスキップされ、**それ以降の質問はすべて 1800 秒まるごと空待ちする**。質問が数個あれば数時間の空転で、
    しかもその間ずっと金を燃やしている。
    `--timeout 0` はすべての質問を即座に空振りさせて「無人応答」を返し、自分で判断して先へ進ませる。
    標準入力がターミナルでないとき、flower はまず 1 行の注意を出力する:
    `! 标准输入不是终端,没人能回答提问。想让它自己判断就加 --timeout 0`
