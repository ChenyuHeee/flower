# HT001 · Writing a terminal IDE from scratch

2026-09-07: an agent, running under flower, wrote from scratch a single-file C/C++ IDE that runs inside a macOS terminal.
It ran for 10.4 hours straight, spent $171.62, and delivered 12,212 lines of product code and 13,291 lines of tests.
The network dropped once in the middle; it picked itself up and ran to the end. This page is not a showcase —
it is every claim the framework makes, measured once at real scale,
**including the two that did not hold up**: "the coordinator frequently ignores permission limits" is false, and one item in its own self-acceptance was judged wrong.

The full record (including the 19MB transcript) is at [ChenyuHeee/cppide](https://github.com/ChenyuHeee/cppide).
Every number below is computed by `tools/analyze_run.py` from `sessions.db` and is reproducible:

```bash
python tools/analyze_run.py /path/to/cppide/runs
```

!!! note "Where the numbers on this page come from"
    HT001's `runs/` lives in the cppide repo linked above, **not in the flower repo**. So the numbers on this page were
    **carried over verbatim** from the run record at the time; they were not recomputed against `sessions.db` while writing this page —
    to recompute them you would have to clone cppide first and then run the command above.
    [HT002](ht002.md) is the opposite: the raw record is in this repo, every number on that page was recomputed item by item,
    and the two that did not match are stated right on the page.

## 1. Context economics: 94.8% of the field never entered the main thread

This is the framework's core claim — the [coordinator](../reference/glossary.md#协调者) holds only decisions,
the field sinks into subagents and onto disk. For the mechanism itself see [Context economics](../guide/context.md).

| | Main thread | Subagents | Subagent share |
|---|---|---|---|
| Model turns | 70 | 3.0K | **97.7%** |
| Body characters | 200.1K | 3.6M | **94.8%** |
| Tool calls | **32** | **1,893** | —— |

This run dispatched 23 subagents; the largest produced 184,377 output tokens, median 72,197, smallest 11,684.

**Of 1,893 hands-on tool calls (1,034 Bash / 471 Read / 258 Edit / 126 Write), only 32 entered the coordinator's field of view — 59:1.** On average, for every dispatch, 82 tool calls happened where it could not see them.

Earlier small-scale tests measured 83%; at real scale it is **94.8%**. The larger the scale, the greater the return on the division of labor —
because the cost of the [task brief](../reference/glossary.md#任务书) and the report back is **fixed per dispatch**,
while the field kept outside grows with task complexity.

## 2. The context curve: the first time we know where "long-horizon" tops out

For each assistant message, `input + cache_read + cache_creation` is the context the model saw on that turn:

```text
turn  1   28.7K   ← startup floor (previously measured at ~34k; matches)
turn 20   35.2K
turn 35  108.6K
turn 50  158.2K
turn 70  185.9K   ← end
```

- 70 turns of monotonic growth, slope roughly **2.2K/turn**
- **No compact occurred at any point** (`DISABLE_AUTO_COMPACT=1`; the only dip is the empty record on the turn the network dropped)
- Used **18.6%** of the 1M window

**Extrapolating at that slope, the wall is at about 440 turns.** These 70 turns produced 12K lines of code,
so in the current form the real ceiling of [long-horizon](../reference/glossary.md#长程) is roughly **6×** this run.
That is a number you can make decisions with; before, it could only be guessed.

To break past it, main-thread growth has to become **sublinear** — more sunk to disk, less left in the conversation.

## 3. 96.1% cache hit rate — $171.62 only works because of it

```text
total input 299.4M tokens
  cache hit   287.5M  (96.1%)
  cache write  11.8M
  uncached      6.2K
output 2.3M (of which thinking 653.9K)
```

299M input tokens cost only $171 because 96% of them were priced as cache.

**Corollary: the economics of a long-horizon run rest on the cache hit rate, and the cache hit rate depends on the stability of the context prefix.**
Any "rearrange the context" optimization — moving old content away, inserting a fresh system prompt near the front —
punctures the cache, and the tokens saved may be worth far less than the cache discount lost. This had never been measured; now there is a number.

This is also an incidental reason flower uses [handoff](../reference/glossary.md#换代) rather than compact:
a handoff **opens a new session and builds the cache from scratch**, so the prefix stays stable within a generation.

## 4. Workbench reuse: 61 scripts, none written and thrown away

The [workbench](../reference/glossary.md#工作台) claim is "write a script once, then just run it, never rewrite it."
The way to verify that is not to ask the agent, but to count how often the scripts in `.flower/scripts/` are Written/Edited versus executed by Bash in the transcript:

```text
61 scripts: written 95 times, executed 331 times
executed more than once (genuinely reused): 56, i.e. 92%
written but never executed: 0
execute/write ratio 3.48
```

`wave5-verify.sh` was written 5 times and run 45 times — iteratively polished, then used over and over, exactly the shape wanted.
**Not a single script was written and thrown away.**

## 5. The coordinator was denied once, and the allowlist was at fault

The suspicion going in was: "the coordinator frequently ignores permission limits and triggers a flood of denied calls." Measurement killed that premise.

**1 denial out of 32 tool calls (3.1%)**, and that one was:

```bash
which g++ clang++ make pkg-config 2>&1; echo ---; ls /usr/include/ncurses.h 2>&1; echo ---; ls /work/runs
```

Segment by segment: `echo` allowed, `ls` allowed, **`which` blocked — it was not in the
[ephemeral command](../reference/glossary.md#一次性命令) table**.

The whole command is purely read-only, a standard environment probe. **The model did exactly the right thing; the allowlist was incomplete**,
forcing it to pay a subagent startup cost (~4.3k tokens) for one `which g++`.

Fixed: added `which` / `command -v` / `type` / `whereis` / `uname` / `arch` / `locale` / `nproc` /
`getconf` / `sw_vers`. `command` and `type` are **only allowed in query form** —
a bare `command rm -rf /` is execution, so omitting that `-v` would be a back door;
`tests/glance.py` has 7 adversarial cases guarding it.

**The thing most worth remembering here is not the patch, it is the method.** A long-running architectural discussion whose starting premise measures 1/32 in real data,
with the attribution backwards — the problem was not the model, it was the allowlist. **Measure first.**

## 6. Resuming after a network drop: verified by a real failure for the first time

```text
01:52:40  tool_result: "Agent terminated early due to an API error"   ← a subagent was interrupted
01:55:41  assistant:   "API Error: ENOTFOUND"                          ← main thread received it
          ↓  the probe hung waiting for the network to come back
          resumed=True, continued the same session, ran another 8+ hours to completion
```

The manifest records `attempts=2 / resumed=True / ok=True`. **Ten hours of work did not restart from zero.**
Before this, [resilience](../reference/glossary.md#韧性) had been filed under "still unverified" — cutting the network requires sudo-editing hosts, and nobody wants to do that during a real run.

That synthetic "API Error" message was stripped by `PruningSessionStore` at load time, so **the model never saw it** —
the [prune](../reference/glossary.md#剪除) design was validated by a real failure at the same time.

Two problems it exposed (see issue #2):

1. Recovery happens at the **framework layer**, not the transport layer. The cost is replaying the entire context, and that context was large.
2. **The interrupted subagent lost its half-finished work.** Resume rescues the main thread;
   subagent-level interruption recovery is a separate problem.

## 7. Is its self-verification real?

This is the part most deserving of suspicion: an agent writes its own tests, runs them itself, and declares itself passing — it is easy for that to become theater.

Afterwards an independent audit subagent was dispatched to statically read all 58 scripts and 22 artifacts. The conclusion is **yes, real, and unusually strict**:

- **Zero tautological assertions.** Nothing like `[ 1 = 1 ]` anywhere in the repo.
- 8 occurrences of `|| true`, **7 of them legitimate** (`grep -c` returning 1 on no match, `ulimit` fallbacks, and the like).
- **It judges behavior, not file existence.** `audit-idle-cost.sh:53` lets the IDE idle in a pty for 60 seconds
  and counts the requests actually received by a local fake server; PASS only if `-le 2`. `fix-p1-idle-verify.sh:100-110` goes further:
  it asserts the idle count is exactly 1 **and** asserts the ghost is still displayed — guarding against "the rate-limiting change killed the feature too."
- **It really spawns child processes.** `wave5-pty-drive.cpp:316` uses `forkpty` to actually drive the TUI; `audit-fake-ai-server.py`
  is a real socket server supporting five fault injections `/err500 /err401 /badjson /drop /slow`;
  every AI path force-clears `CPPIDE_API_KEY`.

Two things exceeded expectations.

**It built positive and negative controls for its own verifier.** `验收审计.md:29-34`: first feed `ZZZ_NEVER_APPEARS_ZZZ` to confirm the driver FAILs,
then feed the real string to confirm it PASSes — avoiding "auditing with a machine that always PASSes." **That is verifying the verifier itself.**

**It proactively disclosed its own weak assertion.** The `for m in $must` at `wave5-b4-ai-states.sh:114`
splits `"AI 错误 请求超时"` on whitespace into three substrings and greps each separately, and `AI` and `错误` are bound to appear on any screen —
nominally "3 checks passed," in reality only 1 has discriminating power. **It wrote this into `验收审计.md:576-582` itself**,
the auditor did not dig it out.

Similar cases: `wave5-verify.sh:296-302` uses 7 lines of comments to explain why B3b was downgraded to SKIP
(a last-screen timing assertion unrelated to product code), noting that "the verdict logic and tolerance range were left untouched, word for word";
`:236-238` records that it **found and fixed a fake assertion it had written earlier** —
`if pgrep ...` silently falls to the else branch on a slim image without `pgrep`, making it always PASS.

**All of this happened on a version without the goal guard.** The only constraint was the
10 decidable acceptance criteria in the [brief](../reference/glossary.md#需求确认书). Which shows: **writing "done" in a decidable form is by itself enough to induce self-auditing and self-disclosure.**
The marginal value of the goal guard has to be measured against this baseline, not against zero.

But the next section shows: **the self-audit is strong on verification technique, and wrong on the final verdict of the single most important item.**

!!! warning "The "auditor" here is not the judge"
    The independent auditor in sections 7 and 8 is a **subagent the coordinator dispatched on its own initiative**, not the
    [judge](../reference/glossary.md#目标看守) of the [goal guard](../reference/glossary.md#判定者) —
    this run had no goal guard at all. They read alike but do different things: the auditor is a post-hoc review,
    the judge is a [verdict](../reference/glossary.md#判定) gate at the end of every step.

## 8. Is its self-scoring correct — acceptance criterion 1 was judged wrong

A second independent auditor was dispatched to judge each of the 10 acceptance criteria against the code.

**Criteria 2–10 all hold**, with code evidence for each. Practice mode not injecting completions is even a **structural** guarantee:
a single sink decision point at `ai.h:117` + a single landing switch at `app.cpp:590-615` + four early-returns at
`editor.cpp:679-683` — not scattered ifs. The P1–P4 issues it found in self-audit **all hold, and all fixes landed**
(P4 half-holds: that blue pair line is dead code; `ghostAttr()` already went through `A_DIM`).

**But criterion 1 was judged wrong.**

```text
criterion text:   "Compile into a standalone executable that runs directly in a macOS terminal"
delivered artifact: ELF 64-bit LSB pie executable, ARM aarch64, GNU/Linux
its verdict:      pass
```

This one was verified by hand, running `file`.

It did not hide it — the title of `交付说明.md` §4 is literally "Biggest unverified risk: never once run on macOS,"
and audit §6 lists six unverified macOS surfaces. **It disclosed the risk but never fed that fact back into the verdict on criterion 1**,
and criterion 1's literal requirement is exactly that thing.

### But this is not evidence that "we need an independent judge"

It is easy to read this offhandedly as "so we need the goal guard." Wrong — and reading it that way is **drawing the target around the arrow**,
exactly the motivated reasoning criticized in the previous section.

**The goal guard as it existed then would very likely have missed this too, under default configuration.** `judge()` defaults to `can_run=False`,
with tools limited to `Read` / `Glob` / `Grep` — **it cannot run `file`**.
It would read the source, see that `Makefile:25-38` really does have a Darwin branch, and rule "achieved." The exact same failure as the self-audit.

### The real structural fact

**Criterion 1 was simply unverifiable in the environment of this run.**

It asserts "the artifact's behavior on macOS," and the entire run happened inside a Linux container.
**No judge whatsoever can verify a macOS binary from inside that container**, self-audit or independent.
The problem is not "who judges," it is that **this criterion was treated as an ordinary decidable criterion, and then judged**.

### Three more the auditor found (none mentioned in self-audit)

- **The quota semantics of `doTab()`**: `app.cpp:909` unconditionally calls `noteActivity()` after `acceptGhost()` → `gen_++`
  → reopening the quota, so **every Tab acceptance triggers another automatic request 500ms later**. The P1 (idle burning money) analysis
  only reviewed the three cancellation points `setMode` / `cancelInFlight` / `askNow` and missed this, the highest-frequency money-spending path.
- The "gray" in criterion 6 only holds literally on a 256-color terminal; the 8-color tier is hard-coded to `A_DIM` (dimmed, not gray).
- `验收审计.md` §7's subheading says "9 acceptance criteria" while the table has 10 rows — a typo, but one that appears in the summary table header.

## Remaining risk

**The delivery target is macOS, but all verification was done inside a Debian aarch64 container; zero verification on real macOS.**
This is a genuine side effect of the container isolation approach: for safety we lock it inside Linux, and what it has to deliver is macOS.
The project's own README §10.24 honestly records this and lists 4 risk points, but never closes the loop.

That gap was later filled by [HT002](ht002.md) — that run installs this very binary on a real macOS machine.

An unexpected benefit: inside the container only `/work` is visible, so across the 19MB transcript
**the host username `/Users/hechenyu` leaks zero times** (`/work` appears 11,495 times).
[Isolation](../reference/glossary.md#隔离) isolated the paths as a side effect.

## What this run could not verify

- **Goal guard**: this run predates it. The coordinator **spontaneously** organized an independent audit; the verification technique is solid,
  but the most important item was judged wrong (section 8). Both conclusions must be recorded together —
  writing decidable criteria into the brief is enough to induce self-auditing, so the goal guard's baseline is not zero;
  and the goal guard as then configured by default **would also have missed that item**, so it is no panacea either.
- **Behavior in the 1M window**: only 18.6% used, the boundary was never touched.
- **Microcompact behavior under `DISABLE_AUTO_COMPACT=1`**: no compact ever triggered, so this remains inference.

## What this run changed in the framework

| Finding | Change that landed |
|---|---|
| `which` blocked (section 5) | `is_ephemeral()` extended with `which` / `command -v` / `type` / `whereis` / `uname` / `arch` / `locale` / `nproc` / `getconf` / `sw_vers`; `tests/glance.py` gained 7 adversarial cases guarding the query forms of `command` / `type` |
| Criterion 1 judged wrong (section 8) | `JUDGE_RULES` rule 1 changed to **judge the artifact, not the source** — run it if you can, and if you cannot, still inspect the artifact itself (platform, size, whether it loads) |
| "I disclosed the risk" bought a pass | The verdict must distinguish "not done" from "cannot be verified here." `Verdict.parse` now recognizes **无法验证 / 没法验证 / 无法判定** as a third state `unreachable` → **surface it to a human, never allow a pass** |
| Criterion 1 was unverifiable in principle in this environment | The goal-setting step now requires **flagging, on the spot, any item that cannot be verified in this environment**, rather than discovering it after the work is done |
| Network recovery lives at the framework layer, subagent half-work lost (section 6) | Filed as issue #2, not closed |

The first three went up against a real API for the first time in [HT002](ht002.md), where "judge the artifact, not the source" saved a run on the spot —
but the same rule also produced a new failure.
