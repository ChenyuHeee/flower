# 换代:上下文满了写交接,不 compact

> 到阈值就让当前会话写一份**可读可改**的交接书,换一个新会话接手。
> 你看得见这个过程,也能改那份文书。

```bash
flower                       # 默认就带换代
flower --window 1000000      # 猜错了才需要给(默认按模型名猜)
flower --no-handoff          # 关掉 —— 退回 SDK 自带的 auto-compact
```

---

## 为什么不用 compact

SDK 自带的 auto-compact 在**窗口 −33k** 处触发(实测值,见
`core/agent.py` 的 `CompactPolicy`),做的事是**把历史总结成一段话**。

它和这个框架其余部分是拧着的:

| | 什么时候决定 | 留下什么 |
|---|---|---|
| `spill_guard` | 工具返回的那一刻 | 大结果落盘,上下文里留一行路径 |
| 冻结件(需求/目标) | 那一步结束时 | 一份文书,下一步只读它 |
| **auto-compact** | **上下文满了才回头** | **一段模型自己写的摘要** |

flower 从头到尾在做的是**当场决定什么该留**。compact 是唯一一处"事后补救",
而且过程不可见、结果不可读、**不可干预** —— 你既不知道它丢了什么,
也没法在它丢之前说一句"那个别丢"。

换代把这件事拉回同一套做法:**又一个冻结件**,和确认书、目标是同一个形状。
而且这正是这个项目自己的做法 —— 仓库根的 `HANDOFF.md` 就是人写的同一种东西。

## 长什么样

```
◆ 上下文 130.0K/200K · 还有约 20K 到换代

◆ 上下文 152.0K/200K —— 写交接准备换代
  ● 现在在做  在给 Makefile 加 macOS 垫片头,让 sigemptyset 宏不再展开成语法错误。
  ● 已定的事  不改业务源码 —— 用户明确说过边界,所以走 Makefile 生成 shim 这条路。
  ● 走不通的  -D_ANSI_SOURCE 会把别的宏一起关掉;改 include 顺序无效。
  ● 下一步    在干净 clone 上跑一次 make 验证 shim 成立。
↪ 交接写在 ~/proj/.flower/notes/交接-干活.md
↪ 新会话接手,上下文从 152.0K 重新开始
```

**全自动,不停下来等你** —— 长程跑不该因为人去吃饭而卡住。
但整个过程你看得见,文书就在磁盘上,想改随时改:接手的人读的就是那个文件。

## 交接书:五段

每一段挡一类"接手的人会犯的错":

| 段 | 挡什么 |
|---|---|
| **现在在做什么** | 不知道自己站在哪 |
| **已经定下的** | 重新讨论已经定过的事(要带**为什么**) |
| **走不通的路** | **最贵的一段** —— 见下 |
| **下一步** | 先花半小时决定干什么 |
| **现场** | 关键文件与产出的**路径**。指针,不是内容 |

### 「走不通的路」为什么单列

因为它是**接手的人最花钱重新发现的东西**,而写的人最容易漏掉。

干活的人有系统性乐观偏差([goal.md](goal.md) 论证过同一件事):
它会写自己做成了什么,忘记写试过什么不行。而后者才是真正贵的 ——
[HT002](case-ht002.md) 里为一个编译问题绕了一小时,那一小时的结论要是没写下来,
接手的人会原样再绕一遍。

所以 `HANDOFF_PROMPT` 里专门用一段话点这件事,还带上了那个实测代价。

`complete()` 只要求「现在在做什么」+「下一步」。**硬性要求「走不通的路」非空
会逼出编造** —— 任务刚开头时它本来就该是空的。

## 没有兵底,所以必须能降级

开着换代就会 `DISABLE_AUTO_COMPACT=1`:两套机制同时跑的话,
某次上下文回落到底是谁干的就说不清了。

代价是**没有安全网**。所以写交接那一轮失败时(网络、模型抽风、五段一段都
解析不出来),不能停,也不能装作没事继续撑到硬上限 —— 那是真的会炸。

做法:用手上已知的东西机械拼一份**残缺交接**,标上 `[降级:交接没写成]`,
照样换代。接手的人被明确告知它拿到的东西不完整,该自己去现场看。

> **残缺的交接远胜于撞窗口。**

## 阈值

```
  0 ──────────────────────────── 200K
                    ↑                ↑
                  150K              硬上限
                 换代
```

`at = window - headroom`。

**`window` 默认按模型名猜**:名字里带 `1m` 的(`claude-opus-5[1m]`)算 100 万,
其余按 20 万。只认这一个明确信号 —— 配错的后果是不对称的:
猜大了会**来不及**(撞窗口),猜小了只是换代偏早(浪费)。

实测值得一提:开发这台机器的网关配的正是 `claude-opus-5[1m]`。按 20 万算的话
每 15 万就换一代,而它其实能跑到 95 万 —— **差 5 倍**。所以这个推断不是锦上添花。

`headroom` 为什么是 50k:auto-compact 在 −33k 触发,换代要赶在它前面;
而"写交接"本身还要再跑一轮。50k 同时满足这两件事。

**`--window` 是换模型/网关时最该调的开关。** SDK 那边拿不到可靠的窗口大小,
只能给默认值。真实窗口更大 → 换代偏早(浪费,不出错);更小 → 来不及,必须调。

### 一道防跑飞的闸

`max_generations=8`。危险在于:**阈值低于这个角色的启动地板**
(协调者实测约 34k,光系统提示 + 工作台索引就占掉了),那么每个新会话
一开口就越线 → 写交接、换代、再越线,**永远不停**(换代不吃重试额度,那是有意的)。

正常长跑用不到 8 代;真撞上了,几乎一定是 `window` 配小了 —— 错误信息里直接这么说。

## 机制

```
干活(session A)
  │  主线程上下文越过阈值   ← 只看主线程。subagent 的上下文是它自己那条
  │                            transcript 的事,跑完就散,不该逼主会话换代
  ├─ 在**消息边界**断开     ← 和 Ctrl+C 打断同一个道理:干净地断,不撕裂状态
  │                            (代价一样:在飞的 subagent 会丢。50k 余量为此而留)
  ├─ 同一个 session 再跑一轮:写交接
  │     为什么是它自己写 —— 只有它有那段上下文。换谁来写都得先读一遍,那就白换了
  ├─ 冻结到 <工作台>/notes/交接-<步骤>.md,上一代移进 notes/archive/交接/
  └─ **新会话(resume=None)**,prompt = 交接书
干活(session B)接着做
```

### 一颗地雷:写交接那一轮必须豁免阈值

写交接是在**越线之后**跑的 —— 那时水位本来就还挂在阈值之上。不豁免的话,
交接那一轮的第一条消息又判"该换代了",于是它一个字都没写出来就被打断,
**每一代都产出降级件**,而且看起来一切正常(降级路径工作得很好)。

实测栽过:`tests/handoff_live.py` 头一次真跑,两代交接全是降级版本。
离线测试没抓到 —— 那里把 `_attempt` 整个换掉了,假的没跑这条判据。
现在判据提成了 `Runtime._handoff_due()`,离线直接验它。

**换代不算重试。** `attempts` 不涨(它数的是失败),代数记在
`StepResult.retired` 里 —— 那是这一步烧掉的 session_id 序列,进 `manifest.json`。
对外的 `session_id` 永远是**还活着的那个接班人**。

### 和「接续」是同一件事的两个方向

[continuity.md](continuity.md) 管的是**跨进程**:同一个目录再跑一次接上上次。
换代管的是**同一次运行内**上下文满了怎么办。

两者自动咬合,不需要额外接线:血缘记的是最终的 `session_id`,
而那正是接班人 —— 所以下次唤醒接在接班人身上。

## API

| 东西 | 说明 |
|---|---|
| `HandoffPolicy(window=…, headroom=…, max_generations=…)` | 传给 `Runtime(handoff=…)`;`False` 关掉 |
| `Handoff` | 五段文书。`parse` / `complete` / `write` / `load` / `prompt_block` |
| `handoff.degraded(step, prompt)` | 写不出来时的残缺件 |
| `StepResult.retired` / `.context` | 烧掉的 session / 最后一轮的上下文规模 |
| `Event("handoff")` | `payload["phase"]` 是 `"near"`(逼近)或 `"done"`(换完了) |

## 旋钮

| 症状 | 拧哪个 |
|---|---|
| 换代太频繁,活总被打断 | `--window` 调到模型真实窗口(`-v` 能看到生效的模型名) |
| 一开局就换代,还报"启动地板" | 同上,`window` 配小了 |
| 交接总是降级 | 看 `runs/manifest.json` 的 `errors`,里面写了降级原因 |
| 接手的人老是重复上一代干过的活 | 交接的「走不通的路」写得太薄。可以直接改那个文件 |
| 就想用 compact | `--no-handoff` |
