# 빠른 시작

이 페이지는 "설치했다"에서 "진짜로 한 번 돌려봤고, 화면에 뜬 것을 이해했다"까지 데려간다. 네 단계, 순서대로:
먼저 가장 싼 한 발로 자격 증명과 바이너리가 양쪽 다 통하는지 증명하고, 그다음 코드 없이 전체 워크플로를 한 번 돌리고,
그다음 실행 중에 말을 끼워 넣는 법을 익히고, 마지막으로 스크립트에 넣어 무인으로 돌린다.

전제는 하나뿐이다. `flower`가 설치돼 있고, PATH에 있고, 자격 증명이 설정돼 있으면 된다. 아직 설치하지 않았다면 [설치](install.md)를 먼저 본다.

## 첫 번째: 가장 싼 한 발로 확인하기 {#冒烟}

처음부터 전체 워크플로를 돌리지 마라. 먼저 단일 agent, 읽기 전용 도구로 한 발 쏴서 자격 증명과 바이너리가 양쪽 다 통하는지 증명한다:

```bash
flower -v -w /path/to/any/repo once "读一眼这个仓库,一句话说它是干什么的"
```

| 이 부분 | 무엇인가 |
|---|---|
| `once` | 단일 agent를 한 번 실행한다. 요구를 묻지 않고, 목표를 세우지 않고, 위임하지 않는다 |
| `-w PATH` | agent의 작업 디렉터리. 주지 않으면 현재 디렉터리 |
| `-v` | 실행 전에 적용된 자격 증명 설정을 출력한다. 토큰은 앞 4자리만 남긴다 |

`once`는 기본적으로 도구를 세 개만 준다 — `Read`, `Glob`, `Grep`. 아무것도 쓸 수 없으므로 이 한 발은 아주 싸다.
실측 기준: Opus 5에 100만 컨텍스트 창, 서드파티 게이트웨이 경유일 때 **한 턴의 최저가는 $0.1741**이고, 더 싼 모델이면 더 낮다.

!!! tip "설치 페이지에서 온 사람은 그냥 넘어가도 된다"
    [설치](install.md) 페이지의 "설치됐는지 확인하기"에서 돌린 게 바로 이 명령이다. 이미 돌렸으면 아래로 내려가라.
    아래 내용은 그 출력을 읽는 법을 알려주는 것뿐이다.

실행이 끝나면 이런 모양이 보여야 한다 — 숫자와 본문은 다를 수 있지만 **아이콘은 다르지 않다**:

```text
ANTHROPIC_AUTH_TOKEN = sk-1***(共 19 位)
ANTHROPIC_BASE_URL = https://your-gateway.example.com
ANTHROPIC_MODEL = claude-opus-5[1m]
- 验一下凭证…
  ~ 先看目录结构,再挑一两个文件读
  * Glob **/*.py
  * Read README.md
  这是一个用 Rust 写的命令行 HTTP 压测工具。
  - 累计 $0.00 · 0:00
  + 完成 4 轮 · $0.0932 · 用时 0:00
```

네 가지를 알아봐야 한다. 이후 단계는 전부 여기에 기댄다:

- 앞 몇 줄은 `-v`가 출력한 적용 설정이다. **게이트웨이를 잘못 연결하면 한눈에 보인다** — 이 옵션이 존재하는 주된 이유다.
- `- 验一下凭证…`는 실행 전에 던지는 실제 API 프로브다. 자격 증명이 거부되면 `! 凭证被拒:…`를 출력하고 그 자리에서 다시 설정할지 묻는다.
  연결이 안 되면 `(探针没打通:… —— 当作网络问题,照常开跑)`를 출력하며, 멀쩡한 토큰을 **다시 설정하게 만들지는 않는다**.
- 아이콘은 전부 ASCII다. `~` 사고, `*` 도구 호출, `>` 위임, `+` 성공, `x` 실패, `?` 질문, `<-` 지난번에 이어서.
  이모지가 아니다 — 이모지와 박스 드로잉 문자는 터미널 글리프 폴백을 유발하고, 실측에서 터미널이 두 번 죽었다. **이 문서의 모든 터미널
  예시는 이 ASCII 세트를 쓰고, 화면에 뜨는 것과 완전히 같다.**
- `+ 完成` 줄의 `$`는 실제 값이다. `累计`와 `用时`는 `once` 경로에서는 항상 0이다
  (이벤트마다 렌더러를 새로 만들기 때문에 상태가 쌓이지 않는다).

이 한 발이 통했다면 자격 증명, 게이트웨이, 모델 이름, 내장 바이너리가 전부 맞다는 뜻이다. 통하지 않으면 설치 범주의 문제이므로 [설치](install.md)로 돌아간다.

## 두 번째: 코드 없이 전체 워크플로를 한 번 돌리기 {#跑一次}

코드를 한 줄도 쓸 필요 없고, **셸에서 따옴표를 칠 필요도 없다**. 프로젝트 디렉터리로 들어가서 그냥 입력한다:

```bash
cd /path/to/your/project
flower
```

무엇을 할지 물어보고, 커서가 `>` 위에 멈춘다:

```text
要做什么? 一句话就够,回车开始(Ctrl-C 退出)
> 帮我做一个 X
```

이 줄은 표준 입력을 읽고, **셸 파싱을 거치지 않는다** — 중국어 따옴표, 공백, 느낌표를 그대로 입력할 수 있다.

엔터를 누르면 세 단계로 진행한다. 화면의 `==` 구분선 한 줄이 곧 [단계](../reference/glossary.md#步骤) 경계이고,
오른쪽의 `1/3`은 진행도다:

```text
== 确认需求 ======================================================== 1/3

  ? X 要跑在什么环境上?
     1) 只在我这台 macOS 上
     2) Linux 服务器
     3) 两个都要
你的回答 (回车=跳过,让它自己判断) > 1
  + 只在我这台 macOS 上

  ? 「做完了」以什么为准?
你的回答 (回车=跳过,让它自己判断) > 能跑起来,并且 pytest 全绿
  + 能跑起来,并且 pytest 全绿

  + 完成 9 轮 · $0.53 · 用时 6:02

== 设定目标 ======================================================== 2/3

  ~ 把这份需求拆成能当场验证的条目
  + 完成 12 轮 · $0.41 · 用时 9:06

== 干活 ============================================================ 3/3

  ~ 先看一眼现在有什么,再决定第一刀切哪
  * Read README.md
  > 派人 coder 实现 X 的第一版,带最小测试
  先让 coder 把骨架搭起来,我再看要不要拆第二个人。
  - 上下文 36.8K · 累计 $0.94 · 12:44
  + 完成 12 轮 · $12.34 · 用时 52:53
  + 完成 37 轮 · $1.40 · 用时 58:19

总花费 $14.68 · 清单 /path/to/your/project/runs/manifest.json
```

세 군데는 좀 더 볼 만하다:

- 마지막 `+ 完成` 두 줄은 중복이 아니다. 첫 줄은 작업 턴이고, 둘째 줄은 **판정** 턴이다 —
  판정은 자기 세션에서 돌지만 **`==` 구분선을 새로 열지 않는다**. `干活` 단계 내부의 한 턴이기 때문이다.
  [실행 매니페스트](../reference/glossary.md#运行清单)에서의 이름은 `干活·判定#1`이다.
- `+ 完成` 줄의 `$`는 **그 턴**의 비용이고, `用时`은 **실행 시작부터 지금까지**의 총 시간이다. 서로 다른 기준이다.
- `- 上下文 … · 累计 … · …` 같은 상태 줄은 [메인 스레드](../reference/glossary.md#主线程)만 따라간다.
  subagent의 컨텍스트는 여기 들어 있지 않다. subagent의 도구 호출은 기본적으로 표시되며, `|` 세로줄 뒤로 들여쓰인다.
  subagent가 **하는 말**은 `-v`를 붙여야 보인다 — 그건 현장이고, 결정이 아니다.

### 화면에 보이는 이 세 단계는 무엇인가 {#三步}

| 화면의 단계 | 누가 도는가 | 무엇을 하는가 | 무엇으로 동결되는가 | 상세 |
|---|---|---|---|---|
| `确认需求` | [확인자](../reference/glossary.md#确认者) | 질문만 하고 손대지 않는다. **명확해질 때까지 묻고, 턴 수 상한은 없다**. 마지막에 네 단락짜리 [요구 확인서](../reference/glossary.md#需求确认书)를 낸다 | `.flower/notes/需求.md` | [사전 확인](../guide/clarify.md) |
| `设定目标` | [판정자](../reference/glossary.md#判定者) | 확인서를 "목표 + 판정 체크리스트"로 번역한다. 각 항목은 그 자리에서 검증할 수 있어야 한다 | `.flower/notes/目标.md` | [목표 가드](../guide/goal.md) |
| `干活` | [코디네이터](../reference/glossary.md#协调者)가 [subagent](../reference/glossary.md#subagent)에게 위임 | 코디네이터가 일을 쪼개 위임하고, 보고를 읽고, 결정한다. 매 턴이 끝나면 **작업에 참여하지 않은** 판정자가 독립적으로 "끝났는가"를 판정하고, 달성하지 못하면 되돌려 계속하게 한다 | 코드 그 자체 | [목표 가드](../guide/goal.md) |

앞의 두 단계는 [사전 확인](../reference/glossary.md#前置确认)과 [목표 가드](../reference/glossary.md#目标看守)
두 메커니즘이 실제로 구현된 것이고, 세 번째 단계는 그 둘이 합쳐서 관리하는 구간이다. 판정은 기본적으로 최대 3라운드까지 돌고(`--rounds`),
`--no-goal`로 전부 끌 수 있다 — 끄면 "다 했다고 말했다"가 정말로 끝난 것이 된다.

판정의 결론은 세 가지뿐이다. 달성, 미달, **이 환경에서는 검증할 수 없음**. 뒤의 두 개는 서로 다른 결론이다 —
"여기서는 검증할 수 없음"은 절대 통과로 판정하지 않고, 멈춰서 너에게 묻는다.

한 번의 전체 실행은 싸지 않다. 실측 기준: [HT002](../cases/ht002.md)는 기존 프로젝트를 macOS에 설치해 돌아가게 하는 데
4단계, 약 1시간, **$38.24**가 들었다. [HT001](../cases/ht001.md)은 터미널 IDE를 처음부터 작성하는 데
**10.4시간, $171.62**가 들었다. 계속 진행할지 결정하기 전에 무엇을 물어보는지 먼저 보고 싶으면 `--clarify-only`를 쓴다.

### 질문에 어떻게 답하는가 {#答提问}

`?`로 시작하는 부분이 너에게 묻는 것이다. 답하는 방법은 세 가지다:

- **번호 입력**(`1` / `2` / `3`) — 그 항목을 고른다. 화면에 `+ <선택한 항목>` 한 줄이 돌아온다.
- **직접 타이핑** — 자유 응답. 선택지 안의 것이 아니어도 된다.
- **그냥 엔터** — 건너뛰고 스스로 판단하게 한다. 화면에 `. 已跳过` 한 줄이 돌아온다.

기본적으로 1800초 동안 기다린다(`--timeout`). 아무도 답하지 않으면
`! 无人应答 —— 它会自己判断,把假设记进「未知与假设」`를 출력하고 계속 진행한다. 멈춰 죽지 않는다.
질문 횟수는 **기본적으로 무제한**이다(`--asks` 기본값 `-1`). 양수를 주면 하드 한도가 되고, 다 쓰면 `! 提问额度用完`을 출력한다.

### 다시 돌리면 지난번에 이어서 {#再跑一次}

같은 디렉터리에서 `flower`를 한 번 더 입력하면 첫 문장이 바뀐다:

```text
接着上次? 直接回车 = 接着做;也可以说点新的;/new = 重开一件事(Ctrl-C 退出)
> 顺便支持代码块高亮
<- 在 ~/proj 接上上次  需求已确认 · 目标 7 条 · 干活上下文 71.4K · 第 3 次唤醒
```

`<-` 줄은 [웨이크](../reference/glossary.md#唤醒) 배너로, 이 디렉터리의 현재 상태를 알려준다.
요구를 다시 캐묻지 않고, 목표를 다시 세우지도 않는다. 프로세스가 kill되거나 머신이 재부팅돼도 마찬가지다.
이때 입력한 문장은 `需求.md`에 덧붙고, **판정 체크리스트 재도출을 촉발한다** —
재도출하지 않으면 판정자가 읽는 것은 여전히 옛 체크리스트이고, 새로 추가한 사항은 애초에 판정에 들어가지 않는다.
세부와 대가(컨텍스트가 계속 커진다)는 [연속성](../guide/continuity.md)을 본다.

지난번에 이어가고 싶지 않으면 `/new`을 입력한다. 앞 구간의 요구, 목표, [계보](../reference/glossary.md#血缘)가
`notes/archive/<时间戳>/`로 **이동**되고(삭제하지 않는다) 처음부터 시작한다.

## 세 번째: 실행이 시작된 뒤에도 말할 수 있다 {#插话}

화면 맨 아래에는 언제나 타이핑할 수 있는 프롬프트 한 줄이 있다. 장식이 아니다 — 출력 하나하나 앞에서 지워지고 뒤에서 다시 그려지므로
**로그에 밀려 위로 올라가지 않는다**. 문구는 두 가지로, "답을 기다리는 질문이 있는지"에 따라 바뀐다:

```text
你的回答 (回车=跳过,让它自己判断) >
(直接说 = 加需求,下个检查点送达;? 开头 = 顺便问一句,不打扰它干活) >
```

답을 기다리는 질문이 없을 때 할 수 있는 일은 두 가지다.

**문장을 그냥 입력 = 요구 추가.** 실행은 끊기지 않고, 다음번에 받은 편지함을 볼 때 확인한다. 접수 확인은 이렇게 생겼다:

```text
+ 收到 (它下次查收件箱时会看到;已追加进确认书)
```

"확인서에 덧붙였다"가 중요하다. 이 문장은 동시에 `需求.md`에 떨어지므로 단계 경계를 넘어 살아남는다 —
다음 단계는 새 세션이고 동결된 문서만 읽으므로, 디스크에 남기지 않으면 말한 게 말하지 않은 것과 같다.

**`?`로 시작 = 겸사겸사 한 마디 묻기.** 읽기 전용 세션을 따로 띄워 답하고, 손에 든 것은 최근 60개 이벤트와
[워크벤치](../reference/glossary.md#工作台) 안의 것뿐이다. 이 우회 경로는
[오라클](../reference/glossary.md#旁路顾问)이 돌리고, 기본 상한은 12턴 / $0.5이다:

```text
? 现在到哪了
# 旁路
  在干活第二轮,coder 刚补完 parser 的测试,正在跑第三次验证。
  ($0.0123,没有打扰正在跑的运行)
```

**답하면 곧 버린다** — 그 문답은 이번 실행의 컨텍스트에 들어가지 않고, 비용도 메인 실행 매니페스트에 들어가지 않는다.
`runs/aside/` 아래에 자기 몫으로 따로 기록된다. 그래서 물어봐도 실행에 영향이 없고, 그 돈이 계정에 잡히는 걸 아쉬워할 필요도 없다.

!!! warning "전각 `？`는 안 된다. 반각 `?`여야 한다"
    우회 문답 인식은 **반각** `?`(ASCII `0x3f`)만 받는다. 입력기가 기본으로 내보내는 전각 `？`는 인식되지 않는다 —
    그 줄은 "요구 추가"로 간주돼 받은 편지함에 들어가고, **에러도 나지 않는다**. 그저 기다리는 답이 영원히 오지 않는다.
    이건 코드의 오타 한 곳이고 결함 목록에 기록해 뒀다. 고쳐지기 전까지는 `?`를 치기 전에 입력기를 영문으로 바꿔라.

Ctrl+C도 짚어둔다. 실행 도중에 처음 누르면 **이번 턴을 끊고 한 마디 하는 것**이지, 종료가 아니다.

```text
! 已打断这一轮。正在跑的 subagent 会丢掉半成品。
  要说什么?(直接回车 = 什么都不说,接着跑;再按一次 Ctrl+C = 退出)
>
```

한 번 더 눌러야 실제로 종료된다. (맨 처음의 `要做什么?` 프롬프트에서 Ctrl-C를 누르면 바로 종료되고 `已取消`를 출력한다.)

## 네 번째: 스크립트에 넣기 {#脚本}

요청을 인자로 바로 줄 수도 있고, 옵션은 요청 앞이나 뒤 어디에 써도 된다:

```bash
flower "帮我做一个 X"                      # 요청을 인자로
flower --rounds 5 "帮我做一个 X"           # 옵션을 앞에
flower "帮我做一个 X" --rounds 5           # 옵션을 뒤에, 동등
echo "帮我做一个 X" | flower --timeout 0   # 파이프로 표준 입력에 먹이기, 완전 자동
```

옵션만 주고 요청을 주지 않아도 된다 — `flower --clarify-only`는 먼저 무엇을 할지 물어본 다음 진행한다.

**"엔터 누른 다음 입력" 경로를 왜 남겨 두었는가.** 명령행의 그 따옴표 한 쌍은 순수한 부담이다. 실측으로 밟아 봤다.
닫는 따옴표를 중국어 `”`로 입력했더니 zsh가 진짜 닫는 따옴표를 계속 기다렸고(`dquote>` 연속 입력 프롬프트로 떨어졌다),
프로그램이 멈춘 것처럼 보였지만 실은 한 번도 시작되지 않았다. 맨몸으로 `flower`를 돌리면 표준 입력을 읽고 셸 파싱을 거치지 않으므로,
중국어 따옴표, 공백, 느낌표, 줄바꿈을 전부 그대로 입력할 수 있다. 파이프도 같은 입구를 지난다 —
표준 입력이 터미널이 아니면 프롬프트 헤더를 출력하지 않고 바로 한 줄을 읽는다.

!!! danger "무인 실행에는 `--timeout 0`을 명시해야 한다"
    파이프, `nohup`, CI에는 질문에 답할 사람이 없다. `--timeout 0`을 주지 않으면 첫 질문은
    "입력이 닫혔다"는 이유로 건너뛰어지지만, **그 뒤의 모든 질문은 1800초를 꽉 채워 기다린다**. 질문 몇 개면 몇 시간의 공회전이고,
    그 시간 동안 돈이 타고 있다.
    `--timeout 0`은 모든 질문이 즉시 비어 "답한 사람 없음"으로 돌아오게 하고, 스스로 판단하며 진행하게 한다.
    표준 입력이 터미널이 아니면 flower가 먼저 한 줄 경고를 출력한다:
    `! 标准输入不是终端,没人能回答提问。想让它自己判断就加 --timeout 0`
