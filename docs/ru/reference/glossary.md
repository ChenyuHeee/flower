# Глоссарий

Эта страница — терминологическая база документации flower. Одна вещь во всей документации
называется одним словом; соответствие китайского и английского зафиксировано здесь —
переводы следуют этой же таблице.

Для каждого термина даны три вещи: **что он обозначает**, **чем он является в коде**,
**чем он не является**. Третье обычно полезнее всего, потому что большинство недоразумений
возникает из-за подмены одного термина другим.

---

## Фреймворк и запуск {#框架与运行}

### Долгосрочность {#长程}

**long-horizon**

Один запуск длится от нескольких часов до нескольких дней, охватывает несколько сессий,
переживает перезапуски процесса — это не «вопрос-ответ». Все механизмы flower существуют
ради того, чтобы такой запуск не развалился на полпути.

Замер на практике: [HT001](../cases/ht001.md) отработал подряд 10.4 часа.

### Запуск {#运行}

**run**

Полный процесс работы `Runtime` от старта до завершения. Внутри одного запуска может быть
несколько [шагов](#步骤), несколько [сессий](#会话), он может быть прерван и затем
[продолжен](#接续). Записи запуска лежат в `runs/manifest.json` и `runs/sessions.db`.

**Не является**: одним вызовом API и не является сессией.

### Сессия {#会话}

**session**

Один контекст на стороне модели. У неё есть собственный `session_id`, её можно resume и fork.
Один [запуск](#运行) может сжечь несколько сессий — на каждой [передаче](#换代) заводится новая.

### Шаг {#步骤}

**step** · `Step`

Исполняемая единица внутри [workflow](#流程). Получает словарь контекста, запускает агента,
пишет результат обратно в словарь. `Step` — это класс, см. [Python API](api.md#step).

### Workflow {#流程}

**workflow** · `Workflow`

Набор [шагов](#步骤), выстроенных по порядку, плюс правила передачи состояния между шагами
и условия досрочного выхода.

!!! note "Фреймворк не даёт готовых workflow"
    flower даёт только механизмы. **Workflow пишете вы**. См. [Проектирование workflow](../guide/workflow.md).

## Роли {#角色}

Роли — это разделение труда между агентами в flower. Каждая роль = кусок внедряемого текста
правил + набор инструментов + набор hook'ов. Все пять ролей — фабричные функции,
см. [Python API](api.md#角色工厂).

### Координатор {#协调者}

**coordinator** · `coordinator()`

Агент, который сидит в [главном потоке](#主线程). Он декомпозирует задачу, раздаёт работу,
читает отчёты, принимает решения, **но сам ничего не делает руками** — ему не выдаются
`Bash` / `Write` / `Edit`. Инструменты только `Agent`, `TodoWrite`, `Read`.

Роль описана как «человек, умеющий пользоваться Claude Code», а не исполнитель.

**Не является**: более умным агентом. Он и [исполнитель](#执行者) по умолчанию работают
на модели одного класса; экономится контекст, а не модель.

### Исполнитель {#执行者}

**worker** · `worker()`

[Subagent](#subagent), который реально делает работу: пишет код, гоняет тесты, ищет информацию.
Инструменты: `Read` `Write` `Edit` `Bash` `Glob` `Grep` `WebFetch` `WebSearch`.

Формат ответа ограничен текстом правил до четырёх разделов — **вывод / основания / результат /
не проверено**, не более 30 строк; запрещено вставлять содержимое файлов, вывод команд,
логи и текст diff'ов.

### Уточнитель {#确认者}

**clarifier** · `clarify()`

Роль, которая до начала работы выясняет требования. Он ничего не делает, только задаёт вопросы,
пока не станет ясно (**без ограничения по числу раундов**), и в конце выдаёт [бриф](#需求确认书).
См. [Предварительное уточнение](../guide/clarify.md).

### Судья {#判定者}

**judge** · `judge()`

Роль, которая решает, «сделано или нет». Он делает одно из двух: перед стартом **ставит цель**
(выдаёт цель + чек-лист проверки), либо после каждого раунда **выносит суждение по этому раунду**
(выдаёт [вердикт](#判定)). См. [Страж цели](../guide/goal.md).

**Ключевое**: судья судит **артефакт**, а не исходники.

В [HT001](../cases/ht001.md) на этом уже споткнулись: критерий приёмки был «запускается прямо
в терминале macOS», а `file` на выданном артефакте показывал
`ELF 64-bit LSB pie executable, ARM aarch64, GNU/Linux` — и тем не менее вердикт был «пройдено».

Два момента нужно проговорить, иначе пример будет прочитан неверно:

1. **Ошибся тогда не страж цели** — в HT001 этого механизма ещё не было; ошибся аудитор,
   которого координатор отправил по собственной инициативе.
2. **Судья в конфигурации по умолчанию, скорее всего, тоже это пропустил бы.** У `judge()`
   по умолчанию `can_run=False`, инструменты только `Read/Glob/Grep` — **он не может запустить `file`**,
   он просто прочитает `Makefile`, увидит там ветку Darwin и признает цель достигнутой.

Реально сработал [HT002](../cases/ht002.md): там судье включили `judge_can_run`, он сам запускал
`file` и `lsof`, смотрел на факты — и эту яму обошёл. **Поэтому фраза «судить артефакт»
становится реальностью только с `can_run=True`.**

### Оракул {#旁路顾问}

**oracle** · `oracle()`

Читающая боковая ветка. Пока запуск идёт, вы можете спросить у него «где мы сейчас» — он
посмотрит последние события и [верстак](#工作台) и ответит. **Сказанное им не попадает в контекст
того запуска** — спросили, на запуск это не повлияло, ответ выбрасывается.

### subagent {#subagent}

Понятие Claude Agent SDK: дочерний агент, которого основной агент отправляет через инструмент `Agent`.
У него **собственный transcript** — вызовы инструментов и попытки записываются туда,
а главный поток получает только итоговый отчёт.

Это первый уровень экономии контекста в flower — и самый экономный.
См. [Экономика контекста](../guide/context.md).

## Четыре механизма {#四个机制}

### Предварительное уточнение {#前置确认}

**clarify**

До начала работы выяснить требования и заморозить их в [брифе](#需求确认书), и только потом
запускать исполнение. Защищает от «сделали не то, что хотели».
См. [Предварительное уточнение](../guide/clarify.md).

### Бриф {#需求确认书}

**brief** · `Brief`

Документ, который [уточнитель](#确认者) выдаёт после опроса, **ровно четыре раздела**.
Последующие шаги читают его и больше не гадают о требованиях.

**Не путать** с [заданием](#任务书). Бриф — это «чего хочет человек», задание — «что делает
конкретный subagent в этот раз».

### Задание {#任务书}

**task brief**

Тот текст, который [координатор](#协调者) пишет [исполнителю](#执行者), раздавая работу.
**Пишется только то, что специфично для этой задачи** — дисциплину, которую собеседник и так знает,
пересказывать не нужно.

Замер: во всех 8 из 8 заданий пересказывалась уже известная адресату дисциплина; в самом коротком
из 521 символа задаче-специфичными были около 120 символов — один раунд впустую занял около
4.8k постоянного контекста.

### Страж цели {#目标看守}

**goal guard**

[Судья](#判定者) после каждого раунда независимо решает, достигнута ли цель; если нет —
возвращает работу обратно. Защищает от «сказал, что сделано, а на самом деле нет».
См. [Страж цели](../guide/goal.md).

### Вердикт {#判定}

**verdict** · `Verdict`

Результат одного суждения [судьи](#判定者), **ровно три раздела**: вывод / обоснование / не пройдено.

Выводов три вида: `ACHIEVED` (достигнуто), `NOT_YET` (ещё нет), `UNREACHABLE` (в этой среде не проверить).
**Последние два — разные выводы**: «здесь это не проверить» ни при каких условиях не считается «пройдено».

### Продолжение {#接续}

**continuity**

Повторный запуск в том же каталоге автоматически подхватывает прогресс предыдущего — так же
и после убийства процесса, и после перезагрузки машины. Защищает от «работало несколько часов,
упало, начинай сначала». См. [Продолжение](../guide/continuity.md).

**Не путать** с [передачей](#换代): продолжение подхватывает прошлый запуск **между процессами**,
передача заводит новую сессию **внутри одного запуска**.

### Передача {#换代}

**handoff**

Когда контекст близок к заполнению, текущая сессия пишет [документ передачи](#交接书), который
человек может прочитать и поправить, после чего работу подхватывает новая сессия. Защищает от
«контекст заполнился и был сжат в один абзац резюме». См. [Передача](../guide/handoff.md).

**Не является** compact. См. [compact](#压缩).

### Документ передачи {#交接书}

**handoff document** · `Handoff`

Документ, который пишется при передаче, пять разделов: `doing` (что делается),
`decided` (что решено), `deadends` (тупиковые пути), `next` (следующий шаг), `scene` (обстановка).

**Обязательны только `doing` и `next`** — жёсткое требование непустых «тупиковых путей»
вынуждает модель выдумывать.

### compact {#压缩}

**compact**

Штатный приём Claude Code: контекст заполнился — предыдущий диалог сворачивается в резюме.

flower **им не пользуется**, вместо него — [передача](#换代). Разница в том, что резюме
сгенерировано моделью, его нельзя прочитать и поправить, и вы не знаете, что потеряно;
документ передачи структурирован, лежит на диске, вы можете открыть его, поправить строку
и дать работе продолжиться.

## Управление контекстом {#上下文管理}

### Главный поток {#主线程}

**main thread**

Контекст той сессии, в которой сидит [координатор](#协调者). Это единственный контекст,
проходящий через весь запуск, поэтому экономить нужно именно его.

Как главный поток определяется в коде: в данных hook'а **нет** `agent_id`.
У hook'ов subagent'ов `agent_id` есть.

### Верстак {#工作台}

**workbench** · `Workbench`

Рабочий каталог на диске, три подкаталога:

| Каталог | Что лежит |
|---|---|
| `scripts/` | Скрипты, которые понадобятся во второй раз; в первой строке `# desc: одно предложение` |
| `artifacts/` | Длинные результаты объёмом больше 2000 символов |
| `notes/` | Ключевые решения, одно решение — один файл |

`INDEX.md` — индекс этих трёх каталогов, он **внедряется в system prompt**, поэтому агент
в каждом раунде знает, что у него под рукой.

!!! warning "Две точки входа, два места по умолчанию"
    Где окажется верстак, зависит от способа его создания, и на этом легко споткнуться:

    | Способ создания | Корень верстака |
    |---|---|
    | `Workbench(workspace)` — этим же путём идут `starter_flow()` / `wake_state()` | `<рабочая область>/.flower` |
    | `Runtime(workbench=True)` | `<run_dir>/workbench` (по умолчанию `runs/workbench`) |

    Командная строка идёт по первому пути, поэтому `flower` создаёт `.flower/`; а прямой вызов
    `Runtime(workbench=True)` из Python даёт `runs/workbench`. Хотите задать место — передавайте
    готовый экземпляр `Workbench`, не полагайтесь на значение по умолчанию.

!!! warning "Индекс subagent'ам не наследуется"
    Индекс идёт через `system_prompt.append` уровня сессии, **subagent его не получает**. Поэтому
    правило «длинные результаты пиши в `artifacts/`» обязан пересказать [координатор](#协调者)
    в [задании](#任务书) — это единственный канал.

### Сброс на диск {#落盘}

**spill**

Когда результат инструмента превышает порог (по умолчанию 4000 символов), hook `PostToolUse`
пишет его в `<корень верстака>/spill/`, а в контексте остаётся одна строка с путём.

Путь **следует за [верстаком](#工作台)**, он не зашит намертво — это ровно `.flower/spill/`
только тогда, когда верстак лежит в месте по умолчанию `<рабочая область>/.flower`. Если включена
[изоляция](#隔离) и верстак через `home=` вынесен за пределы репозитория, spill уезжает следом.

**Режется на месте**, а не потом, когда контекст заполнится и придёт время [compact](#压缩).

### Одноразовая команда {#一次性命令}

**ephemeral command**

Команда, результат которой протухает и не имеет ценности для хранения — `ls`, `git status`, `ps`
и им подобные. Их результаты не попадают в персистентную запись сессии. Решение «пускать ли
главный поток разок посмотреть» и решение «будет ли результат обрезан» принимает одна и та же
функция, поэтому эти два множества всегда совпадают.

### Обрезка {#裁剪}

**trim** · `TrimmingSessionStore`

**Перед resume** переписывает ту порцию сообщений, которая уйдёт обратно в модель
(результаты [одноразовых команд](#一次性命令), сверхдлинный вывод инструментов).

Она переопределяет только `load()`: **оригинал в SQLite остаётся нетронутым**, обрезается лишь
та копия, что уходит в контекст при этом resume. Поэтому обрезка обратима — поменяйте стратегию,
сделайте resume снова и получите полную запись.

### Отсечение {#剪除}

**prune** · `PruningSessionStore`

Держит **сообщения об ошибках** вне контекста. Куча ошибок, возникших во время повторов при
обрыве сети, не должна занимать контекст после resume.

**Не путать** с [обрезкой](#裁剪): обрезка выбрасывает по объёму и ценности, отсечение —
по признаку «это ошибка или нет».

## Runtime {#运行时}

### Изоляция {#隔离}

**isolation**

Помеченные роли автоматически получают отдельный git worktree; это обеспечивается hook'ом,
а не подсказками в промпте. При параллельной правке одного репозитория они не дерутся.

!!! warning "Включили изоляцию — вынесите верстак из репозитория"
    При включённой изоляции через worktree [верстак](#工作台) обязательно нужно вынести за
    пределы репозитория через `home=`, иначе изолированный агент не сможет писать в общий checkout.

### Устойчивость {#韧性}

**resilience** · `Resilience`

При обрыве сети — висеть и ждать, а не падать с ошибкой: DNS- и TCP-пробы следят за связью,
после восстановления сети работа продолжается через resume. Сообщения об ошибках, возникшие
во время ожидания, держит вне контекста [отсечение](#剪除).

### Родословная {#血缘}

**lineage** · `Lineage`

Межпроцессная запись того, «от какой сессии форкнут этот запуск», лежит в `lineage.json`.
[Продолжение](#接续) по ней находит, где остановился прошлый раз.

**Не путать** с [манифестом запусков](#运行清单) — это `runs/manifest.json`, там ведётся
бухгалтерия каждого запуска.

### Манифест запусков {#运行清单}

**run manifest** · `runs/manifest.json`

Бухгалтерия каждого [запуска](#运行): сколько потрачено денег, сколько заняло времени,
какого размера был контекст. Все цифры со страниц кейсов пересчитываются отсюда.

### Пробуждение {#唤醒}

**wake** · `wake_state()`

**Только чтение** перед стартом: смотрит, есть ли в этой рабочей области уже
[бриф](#需求确认书) и цель, и на основании этого решает, начинаем ли мы с нуля или это
[продолжение](#接续). **Не пишет ни байта.**

`wake_state()` — единственное место, где определяется расположение верстака: драйверу, который
хочет узнать, где лежит бриф, тоже нужно идти через него. Если склеить путь самому и ошибиться,
ошибки не будет — всё просто молча перестанет работать.

### Событие {#事件}

**event** · `Event`

Стабильная структура, в которую уплощается поток сообщений SDK. **[Слой взаимодействия](#交互层)
знает только `Event` и не импортирует ни одного типа SDK** — это та граница, благодаря которой
смена UI не требует правок в ядре.

### Слой взаимодействия {#交互层}

**interaction layer**

Тот слой UI, что стоит между человеком и запуском. По умолчанию — терминал; можно заменить на
Web, TUI, HTTP или на полностью автоматический режим без присмотра.
См. [Смена слоя взаимодействия](../guide/interaction.md).

### Хранилище сессий {#会话存储}

**session store** · `SessionStore`

Персистентный бэкенд для сообщений сессии. По умолчанию `SqliteSessionStore` пишет в
`runs/sessions.db`; поверх можно надеть две обёртки — [обрезку](#裁剪) и [отсечение](#剪除).

### Бюджет {#预算}

**budget** · `max_budget_usd`

Верхний предел трат на один запуск; превысили — останавливаемся. Долгосрочный запуск без этого
выходит дорого — [HT001](../cases/ht001.md) стоил $171.62.

## Переносимость {#可移植性}

### Переносимость {#可移植}

**portable**

На другой машине поведение то же самое. Достигается через `setting_sources=[]` — не читаем
ни `~/.claude/` хост-машины, ни `.claude/` проекта. Доменные возможности едут вместе с
репозиторием через [plugin](#plugin), учётные данные приезжают со своим `.env`.

Цена: **учётные данные нужно принести с собой**, конфигурация хост-машины автоматически
не наследуется.

### Добавление {#叠加}

**append**

Доменные инструкции дописываются **после** штатного системного промпта Claude Code,
а не заменяют его:

```python
system_prompt = {"type": "preset", "preset": "claude_code", "append": spec.instructions}
```

Поэтому специализация не оплачивается потерей общих способностей.

### plugin {#plugin}

Пакет доменных возможностей, едущий вместе с репозиторием. Загружается через `plugins=[local]`,
в каталоге могут лежать `skills/`, `agents/`, `hooks/`, `.mcp.json`.
См. [Развёртывание](deploy.md#plugin).
