# Установка

Для установки flower нужен только Python ≥ 3.10. Единственная зависимость времени выполнения — `claude-agent-sdk`; нативный бинарник, который шлёт запросы, лежит прямо в его wheel, поэтому **не нужен ни Node, ни Claude Code CLI**. Эта страница проходит путь с нуля: установка одной строкой, установка из исходников, первая настройка учётных данных и команда, которая доказывает, что «всё действительно встало правильно». Когда получится — идите в [Быстрый старт](quickstart.md).

## Перед установкой: проверьте Python

```bash
python3 -c 'import sys; print(sys.version_info >= (3, 10), sys.version.split()[0])'
```

Вывода вроде `True 3.13.7` достаточно. Если печатается `False` или `python3` вообще нет — сначала поставьте его (`brew install python` / `apt install python3`), иначе скрипт установки просто завершится.

| Нужно | Не нужно |
|---|---|
| Python ≥ 3.10 (`pyproject.toml:5`; `install.sh:22-31` тоже проверяет сам) | Node.js |
| Сеть до эндпоинта API | Claude Code CLI |
| API key или token шлюза (дадите после установки) | Настройки в `~/.claude/` на хосте (учётные данные — единственное исключение, см. ниже) |

Имя пакета `flower`, версия `0.1.0`, единственная зависимость времени выполнения `claude-agent-sdk>=0.2.152` (`pyproject.toml:2-6`). `mkdocs-material` нужен только CI при сборке сайта документации, для работы flower он не требуется.

## Установка одной строкой

```bash
curl -fsSL https://chenyuheee.github.io/flower/install.sh | sh
```

После установки в терминале должно быть примерно так (цвета опущены):

```text
== 用 uv 安装 flower…

== 装好了 /Users/you/.local/bin/flower

下一步:
  cd 到任意项目目录,然后:  flower
  第一次会问你要 API key / 网关地址,配一次存到 ~/.config/flower/.env,处处生效。
  本机已经装了 Claude Code 并配好的话,flower 会直接借它的 token,连问都不问。

  文档:https://chenyuheee.github.io/flower/
```

Ключевая строка — `== 装好了 <абсолютный путь>`: это результат того, что скрипт сам выполнил `command -v flower` (`install.sh:60-61`). Если путь напечатан, значит `flower` уже в PATH.

### Что на самом деле делает установщик

[`install.sh`](https://github.com/ChenyuHeee/flower/blob/main/install.sh) делает всего три вещи: выбирает установщик Python-инструментов, ставит с GitHub и говорит, что делать дальше. **Учётных данных он не касается вообще** (`install.sh:7-8`). Источник установки жёстко зафиксирован: `git+https://github.com/ChenyuHeee/flower.git` (`install.sh:11`).

Установщик пробует варианты по порядку и останавливается на первом сработавшем (`install.sh:33-57`):

| Порядок | Условие | Фактическая команда | Куда попадает исполняемый файл |
|---|---|---|---|
| 1 | `uv` есть в PATH | `uv tool install --force <REPO>` | tool bin каталог uv, обычно `~/.local/bin/flower` |
| 2 | `uv` нет, но есть `pipx` | `pipx install --force <REPO>` | `~/.local/bin/flower` |
| 3 | Нет ни того, ни другого | Сначала `curl -LsSf https://astral.sh/uv/install.sh \| sh` ставит uv, после установки возвращаемся к пункту 1 | Как в пункте 1 |
| 4 | В пункте 3 uv тоже не поставился | `python3 -m pip install --user --upgrade <REPO>` | Пользовательский каталог скриптов — **на macOS это не `~/.local/bin`** |

Во всех четырёх случаях ставится один и тот же console script: `flower = "flower.cli:main"` (`pyproject.toml:12`). После установки можно вызывать и через `python -m flower.cli` — эффект тот же (`cli.py:1263-1264`).

!!! warning "Повторный запуск скрипта установки перезаписывает принудительно, без подтверждения"
    Три команды установки идут с `--force`, `--force` и `--upgrade` соответственно (`install.sh:37`, `:40`, `:54`). Повторный запуск просто затирает существующую установку — именно так и делается обновление, но не ждите, что вас о чём-то спросят.

### Как команда `flower` попадает в PATH

Если `command -v flower` ничего не находит, скрипт предлагает добавить `$HOME/.local/bin` в `~/.zshrc` или `~/.bashrc` (`install.sh:62-70`):

```bash
export PATH="$HOME/.local/bin:$PATH"
```

И `uv tool install`, и `pipx install` кладут файлы именно сюда — для них подсказка верна. **Но для четвёртого пути (`pip install --user`) — не обязательно**: каталог в подсказке зашит жёстко, а пользовательский каталог скриптов pip зависит от платформы. На macOS это `~/Library/Python/3.13/bin`. Проверьте сами:

```bash
python3 -c "import sysconfig; print(sysconfig.get_path('scripts', 'posix_user'))"
```

Вывод вроде `/Users/you/Library/Python/3.13/bin` — добавляйте в PATH именно этот каталог, а не `~/.local/bin`, затем перезапустите терминал или сделайте `source`.

## Установка из исходников

Если нужно читать код, править фреймворк или запускать офлайн-проверки из `tests/` — ставьте из исходников:

```bash
git clone https://github.com/ChenyuHeee/flower.git
cd flower
python3 -m venv .venv
.venv/bin/pip install -e .
```

После этого `.venv/bin/flower --help` должен напечатать строки usage.

У исполняемого файла в venv shebang содержит **абсолютный путь**, поэтому activate не нужен — достаточно симлинка, и команда работает из любого каталога:

```bash
mkdir -p ~/.local/bin
ln -sf "$PWD/.venv/bin/flower" ~/.local/bin/flower
```

Если `~/.local/bin` в PATH, то `cd` в любой каталог проекта и `flower` — будет использоваться интерпретатор из этого venv и этот исходный код.

У установки из исходников есть ещё одно место для учётных данных: **`.env` в корне репозитория** (пятый в порядке поиска, см. [Конфигурация · Приоритет поиска учётных данных](../reference/config.md#凭证查找优先级)). При разработке:

```bash
cp .env.example .env        # заполните ANTHROPIC_AUTH_TOKEN
```

`.env` уже в `.gitignore` и в репозиторий не попадёт. У flower, установленного через pip / pipx / uv, этого места **нет** — он лежит в site-packages, «корня репозитория» там не существует, поэтому при такой установке используйте глобальный файл учётных данных ниже.

## Первый запуск: настройка учётных данных

Все три «живых» входа — `go`, `run`, `once` — в самом начале вызывают `ensure_credentials()` (`cli.py:1013`, `:981`, `:1046`), и это две проверки:

1. **Есть ли они** — проходим по приоритетам; если не нашли, спрашиваем прямо на месте.
2. **Работают ли** — реально делаем один запрос к API. Минимальный запрос с `max_tokens=16` (`env.py:120-123`), стоит почти ничего. Протухший token или неправильный адрес шлюза по переменным окружения не увидеть — без пробы всё взорвётся минут через несколько.

Если учётных данных нет, первый запуск `flower` останавливается на этом экране (`cli.py:1179-1209`):

```text
== 配置 flower ========================================
第一次用?给一次凭证就行。
凭证会存到 /Users/you/.config/flower/.env(只你可读)。装一次,处处生效。

1. 你的 API key 或网关 token (Anthropic 官方的 sk-ant-… 或第三方网关签发的)
   >

2. 网关地址 (直接回车 = Anthropic 官方;第三方网关填它的 BASE_URL)
   >

3. 模型名 (直接回车 = 默认;网关有自己的模型名就填,如 claude-opus-5[1m])
   >

+ 存好了:/Users/you/.config/flower/.env
```

Первый вопрос обязателен: если оставить пустым, красным будет напечатано `没给 token,取消。` и программа выйдет. На второй и третий можно просто нажать Enter. Для официального эндпоинта оставьте второй вопрос пустым; для стороннего шлюза укажите его корневой адрес, **без `/v1`** — проба flower стучится по `<BASE_URL>/v1/messages` (`env.py:162`).

Ключи, которые записываются после ответов (`cli.py:1199-1207`):

| Что вы ввели | Ключ, записываемый в `.env` |
|---|---|
| token начинается с `sk-ant-` | `ANTHROPIC_API_KEY` |
| Любой другой token | `ANTHROPIC_AUTH_TOKEN` |
| Адрес шлюза не пуст | `ANTHROPIC_BASE_URL` |
| Имя модели не пусто | `ANTHROPIC_MODEL`, `ANTHROPIC_DEFAULT_OPUS_MODEL`, `ANTHROPIC_DEFAULT_SONNET_MODEL` — **все три сразу** |

Файл лежит по пути `${XDG_CONFIG_HOME:-~/.config}/flower/.env` (`env.py:39-42`), **перезаписывается целиком**, после записи ставится `chmod 0o600` (`cli.py:1157-1168`). Это и есть тот файл, благодаря которому «настроил один раз — работает везде»: при смене каталога проекта перенастраивать ничего не надо. Значение каждой переменной — в [Конфигурации](../reference/config.md#环境变量).

### Если на машине уже стоит Claude Code, вопросов может не быть вовсе

В поиске учётных данных есть **последний запасной вариант**: читается `~/.claude/settings.json`, затем `~/.claude/settings.local.json`, и из их блока `env` берутся 9 ключей с учётными данными (`env.py:56-75`, `:109-111`). У того, кто уже настроил Claude Code, `flower` запускается и сразу работает, экран настройки вообще не появляется — именно это и обещает `install.sh:77`.

!!! warning "Фраза в продукте «flower не читает ~/.claude/settings.json» — неверна"
    Когда учётные данные не найдены нигде, последняя строка ошибки, которую печатает flower, такая:
    `flower 不读 ~/.claude/settings.json —— 那是可移植性的代价。`
    (`env.py:184-194`, сама строка — `:192`). **Верить нужно коду: он читает.**
    `env.py:56-75` явно читает блок `env` этих двух файлов, просто берёт оттуда только 9 ключей с учётными данными и не подхватывает никаких других настроек. Увидев эту фразу, не делайте вывод, что локальная конфигурация Claude Code игнорируется. Полная цепочка — в [Конфигурация · Приоритет поиска учётных данных](../reference/config.md#凭证查找优先级).

### Когда нужно перенастроить

Подкоманда `flower setup` зарегистрирована (`cli.py:1147-1149`), но её забыли добавить в `_CMDS` (`cli.py:758`), поэтому `flower setup` переписывается в `flower go setup` — «setup» воспринимается как запрос и прогоняется через полный workflow. **Сейчас нет ни одного способа из командной строки добраться до этой подкоманды**, хотя несколько сообщений об ошибках по-прежнему советуют её запустить. Чтобы изменить учётные данные:

```bash
$EDITOR ~/.config/flower/.env
```

Либо удалите token из этого файла и запустите `flower` заново — проверка на отсутствие учётных данных спросит снова (при условии, что их нет и в других местах, например в `~/.claude/settings.json`). Если учётные данные отвергнуты (HTTP 401 / 403), тот же экран всплывёт на месте и предложит перенастроить — но не более одной попытки (`cli.py:1229-1244`).

## Проверка, что всё встало

Два уровня, от дешёвого к дорогому.

**Первый уровень — есть ли команда (бесплатно)**:

```bash
flower --help
```

Если видите эти строки, значит console script установлен и лежит в PATH:

```text
usage: flower [-h] [-w WORKSPACE] [-r RUN_DIR] [-v] [-W] [-T]
              {go,run,once,setup} ...

可移植长程 agent 框架
```

**Второй уровень — учётные данные, эндпоинт и нативный бинарник (несколько центов)**: самый дешёвый настоящий прогон — это `once`: один agent, по умолчанию только три инструмента на чтение `Read` / `Glob` / `Grep`, без [стража цели](../reference/glossary.md#目标看守), без [верстака](../reference/glossary.md#工作台):

```bash
flower -v -w /path/to/any/repo once "读一眼这个仓库,一句话说它是干什么的"
```

`-v` **перед** стартом печатает действующую конфигурацию, оставляя от token только первые 4 символа (`cli.py:1257-1259`; `env.py:197-211`):

```text
ANTHROPIC_AUTH_TOKEN = sk-1***(共 108 位)
ANTHROPIC_BASE_URL = https://cloud.infini-ai.com/maas
ANTHROPIC_MODEL = claude-opus-5[1m]
```

Эти строки подтверждают, что вы не подключились не к тому шлюзу. Дальше — проба учётных данных и собственно прогон:

```text
- 验一下凭证…
  * Read /path/to/any/repo/README.md
  这个仓库是……
  + 完成 1 轮 · $0.1741 · 用时 0:00
```

**Заголовков шагов нет.** `once` идёт через `_run_once` → `rt.run()`, минуя `_drive` / `Workflow.run`, а `Event("step", …)` испускается только в `workflow/base.py:220` — поэтому разделители вида `== 步骤名 ===== 1/1` в `once` не появляются, они бывают только в `go` / `run`.

**Появилась строка `+ 完成` — проверка пройдена.** Она сразу доказывает три вещи: учётные данные работают, эндпоинт доступен, и нативный бинарник из wheel `claude-agent-sdk` запускается на этой машине. Если под `- 验一下凭证…` идёт `! 凭证被拒` или `! 网关地址或模型名不对` — смотрите таблицу разбора ошибок ниже.

!!! note "`once` показывает время и накопленную стоимость как 0"
    `once` создаёт для каждого события новый рендерер (`cli.py:1060`, `:579-581`), поэтому `用时` всегда `0:00`, а `累计 $` в строке состояния никогда не накапливается — **стоимость одного шага настоящая, а время нет**.

    `1 轮 · $0.1741` в строке выше — **измерение с источником**: 2026-09-06 в контейнере Linux/arm64 был отправлен реальный запрос через `cloud.infini-ai.com/maas` (`docker/README.md:24-25`), то есть **нижняя граница стоимости одного раунда** для Opus 5 + окно 1M. Ваш собственный запуск команды выше прочитает репозиторий, раундов будет больше, и стоимость окажется несколько выше этой нижней границы. Полный счёт лежит в `runs/manifest.json`, см. [Конфигурация · Раскладка на диске](../reference/config.md#磁盘布局).

## Когда не ставится

| Симптом | Причина | Что делать |
|---|---|---|
| `需要 Python 3.10+。先装一个…` | Ни `python3`, ни `python` не дотягивают до 3.10+ (`install.sh:31`) | `brew install python` / `apt install python3`, затем запустить скрипт снова |
| Скрипт говорит, что установил, но `flower: command not found` | Установлено в каталог, которого нет в PATH | См. выше «Как команда `flower` попадает в PATH». Если сработал путь `pip --user`, на macOS это `~/Library/Python/3.X/bin` |
| `安装失败。手动试:uv tool install git+https://…` | Все пути провалились, обычно нет сети до GitHub или PyPI | Выполните команду из подсказки вручную и посмотрите настоящую ошибку |
| `缺少凭证:需要 ANTHROPIC_API_KEY 或 ANTHROPIC_AUTH_TOKEN。` (4 строки) | Нет учётных данных в неинтерактивной среде (пайп, CI, `nohup`) — там экран настройки не всплывает, происходит выход | Сначала один раз запустите `flower` в настоящем терминале и настройте, либо запишите `~/.config/flower/.env` напрямую |
| `! 凭证被拒:HTTP 401 …` | Token протух или введён неверно | В интерактивном терминале сразу предложат перенастроить; в неинтерактивном — выход |
| `! 网关地址或模型名不对:HTTP 404 …` | Неверный `ANTHROPIC_BASE_URL` или имя модели | BASE_URL — до корня шлюза, без `/v1`; имя модели — то, которое использует сам шлюз |
| `(探针没打通:… —— 当作网络问题,照常开跑)` | DNS / TCP / таймаут / 5xx | **Это не проблема учётных данных**, flower намеренно не предлагает перенастройку и запускается как обычно, отдавая это слою [устойчивости](../reference/glossary.md#韧性) |
| `! 标准输入不是终端,没人能回答提问` | Запуск в пайпе или CI | Добавьте `--timeout 0`, чтобы система решала сама и не ждала человека |
| `flower setup` запускается и спрашивает «要做什么» | В `_CMDS` забыли `setup` (`cli.py:758`) | Правьте `~/.config/flower/.env` напрямую, см. выше «Когда нужно перенастроить» |
